# Anti-Overplanning Rules

BranchOS exists to improve execution, not to create ceremony.

## Do Less When

- the task can be completed safely in a short checklist;
- no specialized capabilities are needed;
- branch outputs would be obvious restatements of the same work;
- branch maintenance would take more effort than the task itself.

## Prune When

- two branches have the same deliverable;
- a branch has no independent merge contract;
- a branch is speculative and no longer affects the root objective;
- a branch only records style or narration, not a real task concern.

## Keep Branch Notes Short

Branch outputs should be compact. Store evidence and artifacts by reference when possible.

## Budget Escalation

When active working branches exceed the soft cap:

1. merge ready branches;
2. prune stale branches;
3. split only if a real dependency or capability boundary exists;
4. record `over_budget_reason` if the count remains high.
